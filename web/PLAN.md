# Warlords II — web port plan

A port of the Lua/LÖVE remake (`love2d/`) to plain JavaScript drawing on a
single `<canvas>`. No framework and no build step: ES modules served as static
files. The Lua remake is the spec for behaviour; `docs/` is consulted only
where the Lua cites it.

## Shape

```
web/
  index.html            the page: one canvas, loads src/main.js
  src/
    warlords/           the rules core, headless (runs under node too)
    warlords/ai/        the computer player
    ui/                 the dialogs, one module per original dialog
    gfx.js              a small love.graphics-alike over the canvas 2D API
    vfs.js              the preloaded asset store (sync reads after boot)
    display.js, layout  scaling the 640x480 interface to the window
    sound.js            effects, advisor and music through Web Audio
    main.js             the front end (love2d/main.lua)
  assets/               generated by tools/web_assets.py -- see below
  test/                 node tests: the rules suite, and a Lua-vs-JS diff
```

### Porting rules

- Arrays become 0-based. Ids that the Lua kept 0-based and indexed with `+ 1`
  (side indices, city ids, item ids) index the JS arrays directly.
- Lua tables used as sets/maps keyed by objects become `Map`/`Set`.
- `coroutine` (the computer's turn yielding to show walks and battles) becomes
  generator functions: every AI routine on the path to `onWalk`/`onFight`
  is a `function*` and is called with `yield*`.
- File reads go through `vfs`: everything is fetched once at boot, so the
  ported parsers stay synchronous.
- Saves, prefs and the save-slot list live in `localStorage` as JSON.

### Assets (`tools/web_assets.py` → `web/assets/`)

The browser cannot read the 1993 formats directly, so:

| original | becomes | how it is used |
|---|---|---|
| `*.PCK`, `*.FNT` (planar LZ77, 16 colours) | 8-bit greyscale PNG, value = colour index × 17, named `<file>.png` | decoded back to indices at boot, so palettes and colour remaps still work |
| `*.8SN` (u8 PCM 11 kHz) | WAV | Web Audio buffers |
| `SOUND/*.XMI` (AdLib songs) | OGG, rendered with the remake's own OPL synth (`tools/xmi2wav.lua`) | Web Audio, looped where the game loops |
| `pre-rendered-sound/*.ogg` (MT-32 / SC-55) | copied | the Game menu's music choice |
| text and record files (`.SCN .MAP .RD .ITM .DAT .FIN .CRD .HLP .GFX .PAL …`) | copied as-is, listed in a manifest | parsed by JS ports of the Lua readers |

## Notes along the way

- `web/test/compare.sh` plays the same all-computer games in Lua and JS and
  compares them turn by turn (gold, armies, the RNG's state, a hash of every
  army, every city's owner). Every scenario, hidden maps and a save round trip
  come out identical, so the rules core and the AI are a faithful port.
- The songs with a loop in them never end by themselves, so each is rendered
  once through to its own length plus a few seconds of tail, and looped the
  way the Lua plays its Roland recordings: started again at the song's
  length while the old copy's tail rings out.
- Not the Lua's: a Shift or Alt still held from Alt-E no longer opens
  Settings as the computer's turn starts; a sample whose end Web Audio never
  reports (no output device) counts as over once its length has passed; the
  hidden map is kept in a save.
- The random map generator was the web port's own, ported straight from the
  executable (`docs/re/random_map.md`); the Lua and C++ remakes have since
  ported it line for line, and make byte-identical worlds from a seed. It differs
  from the original where the original cannot be followed: its dice are the
  engine's, so a seed does not make the original's map; a slider left to
  chance ("?") is rolled, where the original only draws the "?"; the sites'
  round of the map starts afresh for each world; writes the original makes
  off the edge of its grid are dropped; and the few loops that could in
  principle run for ever give up after 200 000 rounds.
